# AI4S audit test set — design and preregistration

Written 2026-10-21, before any instance was generated or any check was run.
This document is the plan `benchmarks/EXPERIMENT_RECORD.md` §1 requires; the
numbers land in `RESULTS.md` and `records/`, never here.

## 0. Starting point

CrossAudit began as "a git-native, cross-vendor audit protocol for agentic
science" (`src/crossaudit/__init__.py`). Its own measurements since then say
three things that decide what a useful test set looks like:

1. The model rung's recall on real defects is small (2.0% on ExpertLongBench
   T03, `benchmarks/expertlongbench/RESULTS.md`), and every architectural
   change to it slides along one recall/false-positive curve
   (`docs/design/AUDIT_ARCHITECTURE.md` §1).
2. The one change that moved recall by more than a few points was a
   **referent** — telling the auditor what to look for (+21.5 pp) — not a
   structure.
3. Re-running the same model audit flips the BLOCKED/PASS verdict on about 30%
   of instances (D154). **The deterministic check layer (DCL) is the only thing
   that blocks on its own**, and it is the only thing whose verdict holds
   still.

So "improving the harness's performance on science" means, concretely: enlarge
the set of scientifically important defect classes that are caught
**deterministically**, or deterministically **given a referent the project can
supply**, while holding the false-block rate on correct work at the band the
project already enforces for a shipped check (Arm 5, §8g: 4 of 398 correct
annotations blocked, Wilson 0.39–2.56%). A test set for that purpose must:

- enumerate the defect classes that matter in AI-for-science deliverables and
  say, per class, which tier can catch it;
- supply exact ground truth (planted defects, not model-judged labels);
- pair every defective instance with a clean control from the same template,
  so the false-block rate is measured on the same distribution as recall;
- be consumable by the harness's real interfaces — `dcl.run_checks(files)` for
  the deterministic layer and the project's own auditor path for the model
  layer — rather than by a scorer of its own;
- be reproducible from a seed with no network and no licence (synthetic data
  generated from known physics with controlled noise).

### 0.1 What this repository has already measured on science, and what this adds

Four unmerged study branches (`origin/study/ai4s-codeaudit`, `-results`,
`-code`, `-diagnosis`; studies A4S-1 to A4S-4, docs under their own
`benchmarks/ai4s/`) measured the **model rung** on scientific work:

- A4S-1: SciCode steps generated by Haiku, ground truth by SciCode's own tests
  (81 defective / 150 correct). Cross-vendor recall 87.7% at K=8 but 68.7% of
  correct solutions flagged; reframing the task cut both (72.8% / 36.0%).
- A4S-2: 74 correct SciCode instances with **planted reporting faults**
  (×10³, sign, wrong case, +5%, transposed digits) and fabrications. The
  shipped `science` profile caught 49 of 74 faults and **0 of 25
  fabrications** with 0 clean flagged; re-executing the committed script
  caught 70 of 74; the model caught 72 of 74 but flagged 12 of 74 clean.
- A4S-3 / A4S-4: UCI tables with 7 injected data faults; a frozen validator
  reached 65.7% recall at 0% clean flagged, cross-vendor 46.4% at 2.9%, the
  union 80.0%; the held-out diagnosis endpoint gave validator 90/140 vs
  union 105/140.

Three things follow. The model rung's false-flag rate on correct science
(2.9%–68.7% depending on the task) is what decides adoption, exactly as the
code line found. Deterministic validation, where it exists, has the false-flag
rate the product needs (0%) and recall the product lacks (49/74, 0/25
fabrications, 65.7%). And every one of those corpora depends on a third-party
dataset (SciCode's `test_data.h5`, UCI, EvalPlus) or on executing generated
code, so none can run in CI or without network.

This test set is the complement: **synthetic, licence-free, stdlib-only,
deterministic, and aimed at the deterministic rung** — the one rung whose
verdict holds still — with a taxonomy wide enough (17 classes: units, ranges,
derivations, statistics, splits, claims, reproducibility, precision, as well
as the schema/provenance/convergence/number-source classes the shipped
checks cover) to say per class whether code can catch it, and a check pack
that tries. The A4S-2 result that re-execution catches 70/74 is the ceiling
this design deliberately does not reach for (executing generated code inside
the key-holding process is refused by DESIGN.md §5); the question here is how
much of that ceiling a **declaration** the generator can honestly make
recovers without execution.

## 1. Preregistered claims

**H1 (falsifiable).** The shipped `science` profile (schema, units,
convergence, provenance, number_source) catches, deterministically, fewer than
half of the defect classes in §3 — its class-averaged recall over the planted
corpus is below 0.50.

**H2 (falsifiable).** A check pack that lets the generator *declare* what code
can verify (value ranges from the constitution, derivations from committed
data, split integrity, statistical claims, numeric validity) raises
class-averaged deterministic recall by at least 0.30 absolute over the shipped
profile **while the false-block rate on clean controls stays at or below
2.5%** (Wilson upper bound at the corpus n). If recall rises but the
false-block bound is exceeded, H2 is false.

**Primary outcome (one number).** Class-averaged deterministic recall of the
extended profile minus that of the shipped profile, on the planted corpus, with
a cluster bootstrap interval over templates (§5).

**Secondary outcomes.**
- Per-class recall for each profile, Wilson 95% intervals.
- False-block rate on clean controls per profile, Wilson 95%, with per-check
  attribution of every false block.
- Any-blocker recall (blocked for any rule, including an unexpected one) and
  attribution accuracy (the expected rule fired).
- Advisory-only detection (a defect that produced only ADVISORY findings).
- Wall time per instance per profile.

**Arms.** `science` (shipped) and `science-ai4s` (shipped + the new pack).
Same instances, same bytes, same process. Nothing else varies.

**n.** 6 domains × 10 seeds = 60 clean controls; every applicable
(domain, class, variant) planted on every seed, ≈ 1,000–1,500 defective
instances. Why: 60 clean gives a Wilson upper bound of ≈ 6% at 0/60 and ≈ 9%
at 2/60, which is coarse but decides whether a check is in or out of the §8g
band; per class, 10 seeds × ≥ 3 domains × ≥ 1 variant gives n ≥ 30 per class.

**Stopping rule.** Completion. The layer is deterministic: there is nothing to
sample and no budget to exhaust.

**Comparisons made.** Two profiles × 17 classes + 2 false-block rates + 1
primary contrast = 37. The primary outcome was fixed before the run.

**Noise floor.** The deterministic layer run twice on the same bytes must give
byte-identical records; the runner asserts this. Run-to-run spread is 0 by
construction, and the report says so rather than quoting an interval.

## 2. Corpus contract

Every instance is a directory that looks like the audited scope of a
scaffolded science project (`src/crossaudit/scaffold/__init__.py`,
`SCIENCE_TREE`), so the DCL reads it unchanged:

```
<instance_id>/
  TASK.md                              what was asked (the auditor's referent)
  AUDIT_RULES.md                       constitution: scaffold template + domain rules
                                       + one ```crossaudit-ranges block (§4.2)
  experiments/<date>-<slug>/
    metadata.yml                       code_version, inputs: [path@rev, ...],
                                       command, environment, seed  (§4.5)
    results.json                       quantities[], convergence{}, derivations[] (§4.3),
                                       claims[] (§4.6), splits reference (§4.4)
    SUMMARY.md                         prose with the numbers; ends with the
                                       ```crossaudit-numbers block the shipped
                                       number_source check reads
    data/<name>.csv                    raw inputs (declared in metadata inputs)
    scripts/analyse.py                 the analysis, stdlib-only, re-runnable
    predictions.csv, splits.json       ML domains only
```

Paths inside `inputs` are relative to the experiment directory and carry
`@<code_version>` so that `check_provenance` resolves them. Every number in
SUMMARY.md that also appears in results.json is annotated in the
`crossaudit-numbers` block quoting the results.json line that holds it (the
contract in `src/crossaudit/dcl/numbers.py`), so the shipped referent mechanism
is exercised exactly as a compliant generator would use it.

| `dft_convergence` | computational materials | total-energy convergence against k-point density | `energy_per_atom` (eV/atom), `delta_last` (meV/atom), `n_points` (1); `convergence{converged, achieved, threshold}` | `data/kpoints.csv` (kmesh, energy_ev_per_atom) |

Synthetic data is generated from the governing relation with seeded Gaussian
noise, so every "true" quantity is known exactly and every clean instance's
numbers are the correct computation on its own data. The generator runs the
same stdlib code the committed `scripts/analyse.py` runs, so a clean instance
is reproducible from its own files.

### 2.2 Instance identity and pairing

`instance_id = <domain>-s<seed>-<class>-<variant>` for defective instances and
`<domain>-s<seed>-clean` for controls. `pair_id = <domain>-s<seed>` names the
template both derive from. Every defective instance is the clean instance plus
**exactly one** planted edit (single-fault), recorded in the manifest with the
file, a locator, and the before/after values.

## 3. Defect taxonomy

Tier vocabulary:

- `deterministic_existing` — a shipped check should block it today.
- `deterministic_new` — blockable by code once the increment carries a
  declaration a generator can honestly make (the pack in §4).
- `referent` — needs the constitution or task text to decide; a model with the
  rule in front of it may catch it; code cannot.
- `judgement` — expert judgement; recorded so the model rung can be measured
  later, expected deterministic recall 0.

| id | class | tier | expected rule / check | domains | variants |
|---|---|---|---|---|---|
| D01 | `schema_missing_field` | existing | CA-META-001 / `schema` | all | `no_code_version`, `no_quantities`, `inputs_not_path_at_rev` |
| D02 | `unit_missing` | existing | CA-DATA-001 / `units` | all | `empty_unit`, `empty_source` |
| D03 | `unit_wrong` | new | CA-PHYS-001 / `range_rules` | all | `label_swapped` (eV→kJ/mol, K→°C, Å→nm, kJ/mol→eV) value unchanged |
| D04 | `provenance_broken` | existing | CA-DATA-003 / `provenance` | all | `source_not_declared`, `input_file_missing`, `revision_mismatch` (ADVISORY only) |
| D05 | `unconverged_reported` | existing | CA-METH-002 / `convergence` | `dft_convergence` | `converged_false`, `achieved_over_threshold` |
| D06 | `prose_data_mismatch` | existing (annotated) / referent (unannotated) | CA-NUM-002 / `number_source`; CA-DATA-002 (model) | all | `annotated_digit_swap` (prose and its annotation row changed, quote unchanged), `unannotated_digit_swap` (prose changed, numbers block removed), `sign_word_flip` (prose says "decreased" where data increased; referent) |
| D07 | `sign_flip` | new | CA-PHYS-001 / `range_rules` | `arrhenius_kinetics`, `crystal_bandgap_ml`, `biostat_two_group` | `value_negated` (Ea < 0, band gap < 0, sd < 0) |
| D08 | `physical_range_violation` | new | CA-PHYS-001 / `range_rules` | all | `above_max` (band gap 23 eV, a = 48 Å, p = 1.4), `below_min` (a = 0.3 Å, r2 = −3) |
| D09 | `numeric_invalid` | new | CA-NUM-005 / `numeric_validity` | all | `nan`, `inf`, `null`, `string_value` |
| D10 | `derivation_mismatch` | new | CA-DERIV-001 / `derivations` | all | `value_perturbed_1pct`, `value_perturbed_10pct`, `wrong_rows_used` (derivation computed on train rows, reported as test) |
| D11 | `n_mismatch` | new | CA-DERIV-001 / `derivations` | all with `n` | `n_inflated`, `n_deflated` |
| D12 | `split_leakage` | new | CA-ML-001 / `split_integrity` | `crystal_bandgap_ml` | `id_overlap`, `group_overlap`, `test_id_not_in_data`, `duplicate_test_id` |
| D13 | `claim_false` | new | CA-STAT-004 / `claims` | `biostat_two_group`, `crystal_bandgap_ml`, `nmr_shift_calibration` | `significance_overclaim` (p = 0.08 declared `p_below 0.05`), `ci_claim_false` (CI straddles 0, claim `ci_excludes_zero`), `improvement_claim_false` (`less_than` baseline false) |
| D14 | `method_claim_mismatch` | judgement | CA-DATA-002 (model) | all | `prose_method_differs` (SUMMARY says 5-fold CV / PBEsol / Student t, metadata says holdout / PBE / Welch) |
| D15 | `placeholder_or_truncated` | new, ADVISORY (`complete` is in the general pack only) / existing (`number_source` on an unclosed fence) | CA-FILE-004 / `complete` (ADVISORY); CA-NUM-001 / `number_source` | all | `todo_left`, `template_placeholder` (`<VALUE>`), `summary_truncated_mid_block` (file cut inside the numbers fence) |
| D16 | `reproducibility_missing` | new (ADVISORY) | CA-REPRO-001 / `repro_declared` | all | `no_seed`, `no_command`, `no_environment` |
| D17 | `precision_overclaim` | new (ADVISORY) | CA-PREC-001 / `precision` | all with `uncertainty` | `digits_beyond_uncertainty` |

Expected rules are the **minimum** a class should raise; a defect that also
trips another check (a swapped unit label can also break a derivation) counts
as attributed only if at least one expected rule fired, and as any-blocker
detection regardless. Where a variant's expectation differs from its class
(`taxonomy.json` `variant_overrides`: D04 `revision_mismatch` and D15's two
placeholder variants are ADVISORY in the shipped checks), the manifest carries
the variant's expectation and the scorer applies the ADVISORY rule to that
instance.

Two expectations were corrected against the shipped code before the run and
are recorded here rather than silently changed: the `complete` check emits
CA-FILE-004 at ADVISORY (the scaffold's CA-CONTENT-001 is a model-read rule),
and `revision_mismatch` is the one CA-DATA-003 shape the shipped check reports
as advisory. Neither changes a hypothesis; both change which rule a class is
scored against.

What the taxonomy deliberately leaves out, and why: re-executing
`scripts/analyse.py` inside the DCL (arbitrary code execution in the process
that holds keys and writes the ledger — DESIGN.md §5, deny-by-default);
fabricated external citations (needs the governed research tools and a ledger;
`source_provenance` already covers the declared case); figure–text agreement
(no figures in this corpus). Each is a class a later corpus should add.

## 4. The check pack under test (`science-ai4s`)

New module `src/crossaudit/dcl/ai4s.py`, stdlib only, registered like the
builtins, selectable by name, and exposed as one additive profile:

```
science-ai4s = science + [complete, numeric_validity, range_rules, derivations,
                          split_integrity, claims, repro_declared, precision]
```

`science`, `general` and `research` are untouched (AGENTS.md §1.2). Every
check follows D155: **the generator names evidence; code decides what it says.**
A declaration the generator did not make produces nothing — these enforce
declared properties, never coverage — and a declaration that cannot be
verified (unknown method, unreadable file, missing column) is a BLOCKER, the
same fail-closed shape as CA-NUM-001.

### 4.1 `numeric_validity` — CA-NUM-005, BLOCKER
Every `quantities[i].value` must be a finite number (`quantities.is_number_shape`
after JSON parsing; JSON cannot carry NaN/Infinity, so a non-finite value
arrives as `null`, a string such as `"nan"`/`"inf"`, or fails to parse —
all four shapes block). A bool is not a number.

### 4.2 `range_rules` — CA-PHYS-001, BLOCKER
`AUDIT_RULES.md` may carry one fenced block:

    ```crossaudit-ranges
    [{"name": "activation_energy", "unit": "kJ/mol", "min": 0, "max": 500},
     {"name": "p_value", "unit": "1", "min": 0, "max": 1},
     {"name": "mae_*", "unit": "eV", "min": 0}]
    ```

For every quantity whose `name` matches an entry (exact, or `fnmatch` glob,
first match wins): the unit must equal the declared unit byte-for-byte, and
the value must lie in `[min, max]` (either bound optional, inclusive). A
mismatched unit, an out-of-range value, or a malformed block blocks. The block
lives in the constitution because the ranges are the project's rules, versioned
and attributable; the check reads them, it does not invent them.

### 4.3 `derivations` — CA-DERIV-001 BLOCKER, CA-DERIV-002 ADVISORY
`results.json` may carry `derivations`, one row per quantity it can account for:

```json
{"quantity": "mae_test", "method": "mae",
 "input": {"file": "predictions.csv", "truth": "bandgap_ev", "pred": "pred_ev",
           "where": {"column": "split", "equals": "test"}},
 "tolerance": {"rel": 1e-9}}
```

The check recomputes `method` over the named committed file with the stdlib
(`csv`, `math`, `statistics`) and compares with the quantity's value under the
declared tolerance (`abs`, `rel`, or `sig` = significant figures; default
`rel: 1e-9`). Mismatch → CA-DERIV-001. Unknown method, missing file, missing
column, non-numeric cell, or a `quantity` that names no results row → CA-DERIV-001
(cannot be verified is not verified). A quantity with no derivation row →
nothing. A derivation whose file is declared `uncommitted` → CA-DERIV-002
advisory (the generator said where, the project does not keep it).

Method registry (all pure functions over column vectors; `where` filters rows):
`count`, `mean`, `sd` (sample, n−1), `sem`, `min`, `max`, `sum`,
`difference(a, b)` (mean(a) − mean(b)), `welch_t(a, b)`, `welch_df(a, b)`,
`t_pvalue_two_sided(t, df)` (regularised incomplete beta, pure Python),
`ci95_low(a, b)` / `ci95_high(a, b)` (Welch, t quantile by bisection on the CDF),
`mae(truth, pred)`, `rmse(truth, pred)`, `r2(truth, pred)`, `pearson_r(x, y)`,
`linfit_slope(x, y)`, `linfit_intercept(x, y)`,
`arrhenius_ea_kj_per_mol(T_K, k)` (slope of ln k vs 1/T times −R, R = 8.314462618 J/(mol·K)),
`arrhenius_ln_a(T_K, k)`, `bragg_cubic_a(two_theta_deg, h, k, l; wavelength)`
(mean over peaks of d·√(h²+k²+l²), d = λ/(2 sin θ)), `last_delta_abs(y)`
(|y[−1] − y[−2]|), `last(y)`, `scale(x, factor)`.
Every method has its own unit test with a hand-computed value.

### 4.4 `split_integrity` — CA-ML-001, BLOCKER
If the experiment directory holds `splits.json`:

```json
{"data": "data/compounds.csv", "id_column": "id", "group_column": "system",
 "train": ["c001", ...], "test": ["c170", ...]}
```

then: train ∩ test = ∅ by id; no duplicate ids within a split; every id exists
in the data file; if `group_column` is set, the sets of groups are disjoint.
Any violation blocks. Absent `splits.json`, nothing.

### 4.5 `repro_declared` — CA-REPRO-001, ADVISORY
`metadata.yml` should declare `command` (non-empty string), `environment`
(non-empty string or mapping), and `seed` (integer) when `results.json` has
`"stochastic": true`. Each missing key is one ADVISORY finding. Never blocks:
the scaffold rule is advisory and this keeps it so.

### 4.6 `claims` — CA-STAT-004, BLOCKER
`results.json` may carry `claims`, declared statements code can decide:

```json
[{"text": "the difference is significant", "test": "p_below",
  "quantity": "p_value", "alpha": 0.05},
 {"text": "the 95% interval excludes zero", "test": "ci_excludes_zero",
  "low": "ci95_low", "high": "ci95_high"},
 {"text": "the model beats the baseline", "test": "less_than",
  "quantity": "mae_test", "than": "mae_baseline"}]
```

Tests: `p_below`, `p_at_least`, `ci_excludes_zero`, `ci_contains`, `less_than`,
`greater_than`, `within` (`low`/`high` names or literals). A false claim, or a
claim naming a quantity that does not exist, blocks.

### 4.7 `precision` — CA-PREC-001, ADVISORY
If a quantity carries numeric `uncertainty`, and the value is written with
decimal places more than one beyond the first significant digit of the
uncertainty, one ADVISORY finding. Strings are inspected as written; floats
via `repr`.

Honest boundaries, to be stated in each contract string: none of these judge
whether a method is appropriate, whether a derivation is the *right* one for
the claim, or whether an undeclared quantity should have been declared.

## 5. Analysis plan

- A defective instance **counts as caught** by a profile when the profile's
  result has `verdict == BLOCKED` **and** at least one BLOCKER finding whose
  `implementation_code` (rule id) is in the class's expected set or whose
  `check` is in the class's expected checks. "Any-blocker" relaxes the second
  condition. For ADVISORY-tier classes (D16, D17) "caught" means at least one
  finding with the expected rule, of any severity.
- Per-class recall: caught / planted, Wilson 95% (method named, quantity
  named, in the same sentence).
- Class-averaged recall: unweighted mean over the 17 classes.
- False-block rate: clean instances with `verdict == BLOCKED` / 60, Wilson 95%;
  every false block attributed to its check.
- Primary contrast: extended − shipped class-averaged recall. Interval by
  **cluster bootstrap over `pair_id`** (the template is the independent unit:
  every instance derived from one template shares its data), 2,000 resamples,
  percentile interval, seed recorded. A test in `tests/test_score.py` simulates
  this interval's coverage at the corpus n under a null and a plausible effect
  and asserts it is within 0.93–0.97 (EXPERIMENT_RECORD §10). Until that test
  passes the interval is reported as uncalibrated.
- Attribution accuracy: among caught instances, the fraction where an expected
  rule fired.
- Everything in `numbers.json`; `RESULTS.md` is rendered from it and a test
  asserts every number in the prose exists in `numbers.json`.

## 6. Limitations, stated now

- **Synthetic.** The data obey the governing relation plus Gaussian noise;
  real deliverables are messier. A class caught here is caught on a
  well-formed increment, nothing more.
- **Single fault.** Each defective instance carries one planted edit. Real
  work fails in combinations; interactions are unmeasured.
- **Planted = known.** Ground truth is exact because we planted it; this says
  nothing about the base rate of any class in the wild.
- **Deterministic layer only.** The model rung is not run in this record (no
  credentials in this session, and a run costs money the owner has not
  authorised). `run_auditor.py` is prepared and dry-runs; its numbers, when
  produced, go into a separate RESULTS section with their own n.
- **Declarations are honest by construction.** The corpus writes the
  `derivations`, `claims`, `ranges` and `splits` declarations the way a
  compliant generator would. Whether a real generator makes them is a
  separate study (the project's Arm 2–5 line shows that question is not
  trivial).
- **One author, one vendor.** The pack and the corpus were written by the same
  agent line; cross-vendor review of the measurement code (D153) has not yet
  happened.

## 7. Reproduction

```bash
cd benchmarks/ai4s
PYTHONPATH=../../src python generate.py --seed 20261021 --out records/corpus
PYTHONPATH=../../src python run_checks.py --corpus records/corpus \
    --profiles science,science-ai4s --out records/run-2026-10-21
PYTHONPATH=../../src python report.py records/run-2026-10-21 > RESULTS.md
PYTHONPATH=../../src python -m pytest -q tests
```

No network, no credentials, stdlib only. The corpus directory is regenerated
and gitignored; `manifest.jsonl`, `records/run-*/rows.jsonl`, `numbers.json`
and `RESULTS.md` are committed (EXPERIMENT_RECORD §3: records, not corpus
text; here the "corpus text" is synthetic and regenerable, so the manifest's
per-file sha256 is the record).

## 8. Schemas

### 8.1 `manifest.jsonl` — one row per instance
```json
{"instance_id": "arrhenius_kinetics-s3-D07-value_negated",
 "pair_id": "arrhenius_kinetics-s3", "domain": "arrhenius_kinetics", "seed": 3,
 "clean": false, "defect_class": "D07", "variant": "value_negated",
 "planted": {"file": "experiments/2026-10-21-arrhenius/results.json",
             "locator": "quantities[0].value", "before": 84.21, "after": -84.21},
 "expected": {"tier": "deterministic_new", "rules": ["CA-PHYS-001"],
              "checks": ["range_rules"], "severity": "BLOCKER"},
 "files_sha256": {"experiments/.../results.json": "<hex>", "...": "..."}}
```
A clean row has `"defect_class": null, "variant": null, "planted": null,
"expected": null`.

### 8.2 `records/run-*/rows.jsonl` — one row per instance per profile
```json
{"instance_id": "...", "profile": "science", "verdict": "BLOCKED",

### 8.2a Declaration conventions as implemented (recorded 2026-10-21, before the run)

The pack's contract strings (`crossaudit.dcl.contracts(["derivations", ...])`)
are authoritative; this is the summary the corpus was written to. `input.file`
and `splits.json`'s `data` are relative to the experiment directory holding
the results.json. Column keys are the method parameter names (`truth`/`pred`,
`x`/`y`, `T_K`/`k`, `two_theta_deg`/`h`/`k`/`l` + `wavelength`, `y`); a
single-column method takes `x` (or `column`, never both). Two-sample
arguments `a`/`b` are a column name or `{"column", "where"}`. Scalar operands
(`t`, `df`, `scale`'s `x`) name a quantity or are numeric literals.
`where` is exactly `{"column", "equals"}` with a string or integer `equals`.
Tolerance is exactly one of `abs`/`rel`/`sig`; the corpus writes
`abs = 0.6·10^-d` for a value with d decimals and `abs = 0.5` for counts.
Dimensionless units are written `"1"`. `uncommitted` is
`{"file": ..., "uncommitted": true}`. A claim's string operand is always a
quantity name; `ci_contains` takes `value`.

## 9. Amendments (dated, written after the run; the sections above are unchanged)

**Amendment 1 (2026-10-21).** H2's false-block condition (Wilson upper bound
≤ 2.5%) cannot be met at the preregistered n = 60 clean controls: 0 of 60
gives 6.0%. The criterion should have been stated with an n that can satisfy
it (n ≥ 150 at a zero count). The preregistered decision is reported as
written; an exploratory run at 30 seeds per domain (180 clean controls) is
recorded beside it and labelled. See `records/run-2026-10-21/DEVIATIONS.md`
item 1.

**Amendment 2 (2026-10-21).** The cluster bootstrap over templates has zero
variance on this corpus because the deterministic layer's outcome is a
function of (class, variant) alone; the interval is a point and the coverage
simulation (which assumed template-level variation) does not apply to this
run. A future corpus that wants an informative interval needs within-class
heterogeneity that the checks can actually be sensitive to (different
tolerances, noise levels, declaration coverage) — or should state up front
that the deterministic rung's recall is a count, not an estimate.
